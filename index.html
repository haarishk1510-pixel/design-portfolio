Spline-based process planning for CNC machining

Vehicle & mfg. designComputational geometry
PythonNumPySciPyMatplotlibezdxf

Problem

At the Combat Vehicles Research & Development Establishment, machining paths for components were planned and checked by hand. Rough paths mean jerky tool motion and slow manual review.

What I built

  • A spline-based Computer-Aided Process Planning (CAPP) framework that optimises CNC machining paths.
  • A Python modelling pipeline with NumPy, SciPy and Matplotlib that generates DXF files automatically through ezdxf.
  • Automated trajectory visualisation and analysis, which made paths smoother and cut manual analysis effort.
  • An exploration of how CAD, CAPP and CAM fit together in a digital manufacturing workflow.

Why it matters for vehicle design

Smooth, continuous curves are the core of both machining and vehicle surfacing. This project gave me hands-on practice with spline geometry, curvature and the CAD-to-manufacturing chain that every vehicle part goes through.

AI-powered surveillance threat analytics

AI-based designDashboard UX
PythonOpenCVDeepFaceFlaskSQLiteREST APIs

Problem

Raw camera feeds are too much for a person to watch. Operators need the system to notice people, judge activity and surface only what needs attention.

What I built

  • A real-time analytics platform that detects humans with computer vision and monitors for threats.
  • Automated alerts, evidence capture and activity classification, with predictions stored in SQLite behind REST APIs.
  • A dashboard for real-time analytics, designed so alerts and security insights are the first thing an operator sees.

Design takeaway

The model is only half the product. Deciding what to show, when to interrupt the operator and how to attach evidence to each alert shaped the interface as much as the detection code did.

Personal project · deployed

DFA-based intrusion detection system

UI / UXWeb app
Node.jsExpress.jsJavaScriptHTMLCSSRender
Open live app ↗ Source on GitHub ↗

Problem

Brute-force and suspicious login patterns are easy to miss in plain logs. I wanted a system that models login behaviour formally and shows administrators what is happening.

What I built

  • A web-based intrusion detection system that uses a Deterministic Finite Automaton to track login attempts and flag suspicious authentication patterns.
  • Secure authentication flows, middleware-based request validation and role-based admin features in Node.js and Express.js.
  • A responsive dashboard for user activity and intrusion events, deployed on Render.

Design takeaway

A formal model makes the system's behaviour predictable, and a predictable system is easier to explain in an interface. Each state maps to something an admin can see and act on.
